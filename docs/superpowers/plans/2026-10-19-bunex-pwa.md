# BUNEX Progressive Web App Implementation Plan

> **For implementers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task with TDD.

**Goal:** Make the existing BUNEX website installable and reliably useful offline without adding a PWA library or changing restaurant content.

**Architecture:** Next.js supplies the web manifest through `app/manifest.ts`; a production-only React client component registers a versioned, same-origin service worker. A self-contained static offline page is precached so fallback rendering never depends on Next.js chunks.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript, browser Service Worker and Cache Storage APIs, Node test runner.

**Spec:** `docs/superpowers/specs/2026-10-19-bunex-pwa-design.md`

## Global Constraints

- Preserve all current BUNEX content and page behavior.
- Add no runtime dependency.
- Intercept only same-origin `GET` requests.
- Keep cross-origin ordering, Maps, Instagram, and review traffic network-only.
- Register the service worker only in production.
- Use `apply_patch` for text edits and generated tooling only for binary PNG icons.
- Update README and verify tests, production build, headers, and browser registration.

## Review Focus

- Confirm a failed navigation cannot leave the user with a rejected response when the offline fallback is cached.
- Confirm the worker never handles cross-origin or non-GET traffic.
- Confirm cache cleanup cannot delete unrelated cache names.
- Confirm a new service-worker version replaces old BUNEX caches without retaining stale application HTML indefinitely.
- Confirm maskable artwork keeps the BUNEX mark inside the safe zone and icon files have their declared dimensions.
- Confirm development mode does not register a worker and production metadata exposes the manifest.
